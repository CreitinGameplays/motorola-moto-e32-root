GSI boot as independent proof of the bootloader unlock - Moto E32 (hawaii), 2026-10-29
===============================================================================

An Android 15 GSI (Google "treble_arm64_bvS" / TrebleDroid_vanilla,
test-keys, userdebug) was installed with DSU-Sideloader
(https://github.com/VegaBobo/DSU-Sideloader) and booted successfully.

DSU-Sideloader lists "Unlocked Bootloader" as a hard requirement, and
Android's gsid refuses to install/boot a DSU image on a locked bootloader
(only OEM-signed GSIs may boot there). A foreign, unsigned system image
booting is therefore an independent confirmation of the unlock, and it
exercises exactly the property the marker enables: U-Boot skips the
verified-boot policy for a system it did not sign.

6. Known GSI-side defect: the Quickstep launcher crashes

     java.lang.SecurityException: Permission Denial: getRootTaskInfo() from
       pid=2704, uid=10105 requires android.permission.MANAGE_ACTIVITY_TASKS
       at com.android.launcher3.uioverrides.QuickstepLauncher

   Root cause (not related to the unlock):

     * com.android.launcher3 lives in
       /system/system_ext/priv-app/Launcher3QuickStep/Launcher3QuickStep.apk
       but is signed with a different key than the platform:
         launcher3 signatures:[d7f1f224]
         platform  signatures:[b4addb29]
       so the signature|privileged permission MANAGE_ACTIVITY_TASKS is not
       granted by signature match;
     * the GSI ships no privapp allowlist entry for it - none of the 30
       files in /system/etc/permissions/ mentions the launcher;
     * it cannot be granted at runtime either:
         pm grant com.android.launcher3 android.permission.MANAGE_ACTIVITY_TASKS
         java.lang.SecurityException: Permission ... is not a changeable
         permission type
     * consequence: cmd package resolve-activity -c android.intent.category.HOME
       -> "No activity found" (no usable home screen).

   Workarounds: sideload any launcher APK (this GSI has no Play Store:
   com.android.vending is absent), or reboot back into the stock Motorola
   system where com.motorola.launcher3 works.

   (artifacts/marker.bin == artifacts/marker_readback_after_gsi.bin), and
   the uboot_log partition still shows
   androidboot.vbmeta.device_state=unlocked.
