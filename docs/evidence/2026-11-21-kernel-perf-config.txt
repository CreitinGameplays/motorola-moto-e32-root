# Kernel performance config build verification (2026-11-21/22)

VPS build of `motorola-moto-e32-kernel` `4.14` with the new performance
defaults in `build.sh` plus the `tcp_bbr.c` helper fix.  Host: 2 vCPU,
3 GB RAM, clang+lld 11.0.1, `OUT=/home/creitin/kbuild`,
`STABLE=/home/creitin/kernel-out`.

First attempt failed because the vendor drop's BBR file was never
compiled before:

```
net/ipv4/tcp_bbr.c:274:43: error: implicit declaration of function
        'bbr_min_tso_segs' [-Werror,-Wimplicit-function-declaration]
        segs = max_t(u32, bytes / tp->mss_cache, bbr_min_tso_segs(sk));
```

The 5.4.y helper was added (`bbr_min_tso_segs()`, matching the
`min_segs` already computed by `bbr_set_tso_segs_goal()`), then the
incremental rebuild finished with EXIT=0.

## Flash + on-device verification (2026-11-21/22)

Packed `Image.perf` into `boot_perf_magisk.img` with
`pack_and_sign_boot.py --base boot_custom_magisk.img` (the base is
byte-identical to the previous `boot_b`, hash `024005f4...`; only the
kernel payload changed, ramdisk and DTB match the base byte-for-byte).
Signed image: 67,108,864 bytes, sha256
`49d74b204d6e11d3fcc626def9ccf74ae9f73abd40afa48e832f7bd6fc1bb3c6`.
Staged the matching modules in the Magisk modules:
`mali_kbase.ko` `e50bd062...` and `sprdwl_ng.ko` `f3f5661e...` (hashes
verified on the device).

Flashed with `run_boot_b_test.ps1 -SkipWait`: slot `_b`, root uid 0,
SELinux Enforcing, boot_a rescue v3 (`46519e13...`) verified, `dd`
read-back hash matched, slot b armed to one attempt, reboot issued via
`su -c reboot`.  Android came back in ~104 s (and a second reboot in
~56 s).  Full log: `docs/evidence/2026-11-21-perf-flash.txt`.

Vendor modules still load (camera, flash, sensor, BT `sprdbt_sdio_tty`,
FM `sprd_sdio_fm`, SAR `aw9610x_sar`).  A one-time
`WARNING: CPU: 1 PID: 55 at sdiohal_list_push+0xdc/0x254` at t+8.7 s is
pre-existing (identical warning on the 2026-11-17 boot at t+8.5 s), not
a panic.  `dmesg | grep -cE 'Internal error|Kernel panic'` = 0.

Wi-Fi: the 5 GHz network is a bonus - the user reports stock configs on
this device only support 2.4 GHz.  With the new Image the in-tree
`sprdwl_ng` (708608, the port with the SDIO remove fix) associates to
`Família Santos_5G` at 5200 MHz (Wi-Fi standard 5, 292-390 Mbps,
`wlan0` with `fq_codel`) and stays on it across three `svc wifi
disable`/`enable` cycles; no reboot, no Oops.  The in-tree module also
remains loaded (size 708608, i.e. no handover to the 409600-byte vendor
module this time).

BT: `sprdbt_sdio_tty` loads; attempting `svc bluetooth enable` from the
adb shell is denied by Android (`SecurityException: Need BLUETOOTH
ADMIN permission`, `svc` rc=137) - a pre-existing shell restriction,
not a kernel error.  BT stays in BLE_ON state.

Slot/cleanup: after the successful boot the A/B block shows slot b
`8e 00 9f 00` (successful=1); boot_a rescue untouched.  The flash
staging image, slot helper, `ab_tries1.bin` and the temporary abiprobe
`.ko` were removed from `/data/local/tmp`.
