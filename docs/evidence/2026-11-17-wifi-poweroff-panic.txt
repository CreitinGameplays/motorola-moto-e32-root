# Wi-Fi off -> kernel panic (2026-11-17): logs before and after the fix

Phone: Moto E32 (hawaii, UMS9230, Android 11, 4.14.199+-ab612c2).
Boot module at the time: in-tree sprdwl_ng from
/data/adb/modules/sprd-wlan-combo (Magisk, "Ver. v1.0", 708608 in
/proc/modules). Bootloader slot: boot_b (Magisk), slot_a untouched.

Notes on the decode:

- `ISS 0x47` = write (`WnR=1`), DFSC 7 = translation fault level 3.
  The address is unmapped, not RAM-scribbled.
- With `VA_BITS=39`, `MODULES_VADDR=0xffffff8000000000` and
  `MODULES_END=0xffffff8800000000`; the faulting `ffffff8001048458` is in
  that window, so the timer detached by `run_timer_softirq` lived in module
  memory freed by the rmmod (`[last unloaded: sprdwl_ng]`).
- 0.24 s elapsed between `sprd_wlan_remove` and the fault: the per-second
  `iface_wd_tick` delayed work of the unloaded module.

No Oops, no panic; adb stayed connected and `uptime` kept counting.

`svc wifi enable` then loaded the vendor module (the HAL's own
finit_module("/mnt/vendor/socko/sprdwl_ng.ko")), and Wi-Fi reconnected:

    $ adb shell grep sprdwl /proc/modules
    sprdwl_ng 409600 0 - Live ... (O)        <- vendor .ko (our port: 708608)
    $ adb logcat -d | grep wifi_load_driver
    I android.hardware.wifi@1.0-service: wifi_load_driver success: Success
    $ adb shell settings get global wifi_on
    1
    $ adb shell dumpsys wifi | grep 'Wi-Fi is'
    Wi-Fi is enabled

3 further off/on cycles (`svc wifi disable` / `svc wifi enable`, 6 s / 8 s
apart) all returned; final check:

    $ adb shell cat /proc/uptime
    286.04 2080.18          (same boot, no reboot)
    $ adb shell settings get global wifi_on
    1
