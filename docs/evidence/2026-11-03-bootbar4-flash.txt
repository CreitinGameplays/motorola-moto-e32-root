--- result ---
The kernel booted and was visible on the panel, but NOT as designed
(user report, 2026-11-03 ~22:00): instead of a horizontal bar the panel
showed four vertical lines ("|  | |  |": one at the left edge, one at
the right side, two spaced in between) whose segments grew downwards
while boot progressed.

That observation refuted the transposed-scanout model this image was
built for.  Re-rendering the exact v4 write pattern showed the model
predicts two clean horizontal lines (which is not what appeared), while
a PORTRAIT 720x1600 / stride 2160 buffer predicts a lattice of dotted
vertical columns exactly like the report - so the 4800-byte stride,
not the orientation, was the error.  See docs/18 sec. 11 for the
corrected geometry and the v5 fix.

What v4 did prove: the flash path worked, the custom kernel booted with
the bar code running, and slot b recovered normally (no BROM needed).
