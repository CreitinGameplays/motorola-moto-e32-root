# Host ADB on the 7.1 test kernel (Moto E32 / UMS9230)

Status: **working** on `boot_71_live17.img` (Linux `7.1.0-rc1-sprd+`).
`adb shell` over the RNDIS link reports `uid=2000`, `ro.boot.slot_suffix=_b`.
`sys.boot_completed` is still empty — full Android boot remains blocked by
Trusty/keymaster and the 4.14 HALs — but a usable host shell on the 7.1
Android userspace is now available.

## Why this route

* A USB-FFS (`ffs.adb`) gadget never produced a usable host ADB device,
  even with the exact stock `g1` configuration (`ffs.adb` + 3 `gser`
  functions, VID/PID `18d1:4ee8`, correct serial, OS descriptors).
  adbd did receive `FUNCTIONFS_BIND`/`ENABLE`, but bulk reads failed with
  `received packet of unexpected length while reading header`.
* COM6 (CDC-ACM) is reliable, so it is used only to launch the script.
* ADB over TCP avoids FunctionFS entirely.  The phone reaches the host
  through a kernel-side RNDIS gadget, which (unlike FFS) needs no userspace
  protocol handling.

## Device-side steps

Run `scripts/device/enable_71_host_adb.sh` from the live17 COM6 root shell
after ~8 s (the helper's late shell).  It is also kept on-device at
`/cache/h71/tcp_rndis.sh`, which survives reboots:

```sh
setsid sh /cache/h71/tcp_rndis.sh &
```

The script:

1. Mounts a tmpfs at `/data` and writes the host public key to
   `/data/misc/adb/adb_keys`.  The real `/data` never mounts on 7.1
   (dm-default-key needs Trusty), `ro.adb.secure=1`, and there is no UI
   to tap Allow.
2. `setprop service.adb.tcp.port 5555`.  **Regular properties work** from
   this shell (context `u:r:kernel:s0`); only `ctl.*` control properties
   are rejected.  A raw `PROP_MSG_SETPROP` also got `n=0` from the
   property service.
3. adbd is an updatable APEX service: `/system/bin/adbd` does not exist
   and apexd only activates bootstrap APEXes.  Unzip `apex_payload.img`
   from `/system/apex/com.google.android.adbd.apex` to `/cache/h71`,
   `losetup -r` it on `/dev/block/loop26`, mount it read-only at
   `/apex/com.android.adbd`, and start
   `LD_LIBRARY_PATH=/apex/com.android.adbd/lib64
   /apex/com.android.adbd/bin/adbd`.
   It logs `adbd listening on tcp:5555`.
4. Rebuild the `h71` configfs gadget **while unbound**: VID/PID
   `04B3:4010`, config `c.1` containing **only** `rndis.0`.  Those IDs
   are in Windows' inbox `netimm.inf`, so the "IBM USB Remote NDIS
   Network Device" driver binds automatically.  With `acm0` also linked,
   Windows bound that driver to the composite parent and failed with
   code 10; RNDIS-only avoids it.
5. `ip link set usb0 up; ip addr add 192.168.42.1/24 dev usb0`.

The UDC is `musb-hdrc.10.auto` on the 7.1 kernel (stock 4.14 calls it
`musb-hdrc.0.auto`).

## Host-side steps

Windows takes an APIPA address on the RNDIS adapter, so no admin rights
are needed to set a static IP.  Both ends have IPv6 link-local addresses
and can talk directly:

```powershell
# Find the RNDIS adapter's interface index (e.g. 52):
Get-NetAdapter | Where-Object {$_.InterfaceDescription -match 'RNDIS'} |
    Select-Object Name, ifIndex, Status
ping -6 fe80::ff:fe00:1%52
adb connect "[fe80::ff:fe00:1%52]:5555"
adb devices
adb -s "[fe80::ff:fe00:1%52]:5555" shell 'cat /proc/version; id'
```

`fe80::ff:fe00:1` is the phone's `usb0` link-local address (derived from
the `dev_addr` set in the script).  Replace `%52` with the actual Windows
interface index.  To avoid typing the scope in every adb command, set
`$Env:ADB_SERIAL` to the full `[fe80::...%N]:5555` string.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| RNDIS device shows `Error`, code 28 | No inbox driver for VID `0525:A4A4`; use `04B3:4010` (netimm.inf). |
| RNDIS device shows `Error`, code 10 | Composite parent grabbed the RNDIS driver: remove `acm0`, keep only `rndis.0`. |
| `ln: ... to configs/c.1/rndis0: Invalid argument` | Configfs rejects links while the gadget is bound; unbind first (`echo '' > UDC`). |
| `CANNOT LINK EXECUTABLE adbd: libadb_protos.so not found` | Set `LD_LIBRARY_PATH=/apex/com.android.adbd/lib64`. |
| adbd logs `Failed to get adbd socket` | Harmless: missing framework auth socket; keys still work. |
| Host shows `unauthorized` | Wrong/missing `adbkey.pub` at `/data/misc/adb/adb_keys`. |
| `adb connect` times out | Check `ping -6 fe80::ff:fe00:1%<ifindex>` and that adbd logged `listening on tcp:5555`. |
